## 2. The venture
**Punarnava** (Sanskrit: "that which becomes new again") — a plastic recycling business being set up in Bangalore.
Value chain: collect waste plastic → sort by type → shred → wash → dry → extrude → pellets → sell pellets to manufacturers + sell EPR credits to brands.
(EPR = Extended Producer Responsibility: Indian rules that make brands responsible for their plastic waste and push recycled content. Recyclers earn certificates brands buy.)
Starting focus is not final; research files in /research decide it. Never assume — read /research first.

## 4. Public vs private (NO login system — do not add one)
- **Public (deployed on Vercel):** only `/` (landing) and `/sources`. Nothing else is built or shipped there.
- **Private (local only):** `/os/*` lives in the route group `src/app/(private)/os`. They run only on the founder's machine via `npm run dev` (or double-click `start-os.bat`, which opens http://localhost:3000/os). No password, no roles, no investor view — local means owner access.
- **How Vercel is kept public-only:** `npm run build` runs `scripts/prune-private.mjs` first. When the `VERCEL` env var is set it deletes `src/app/(private)` before `next build`, so those routes are not built, not reachable and not in the build output. Locally (no `VERCEL`) it does nothing. Check with `VERCEL=1 npm run build` in a throwaway copy or reset afterwards (`git checkout -- "src/app/(private)"`).
- **Rules for every future session:**
  - Do NOT add login, passwords, sessions, cookies, middleware/proxy guards, roles, "investor view" or auth env vars. Privacy comes from the private routes not being deployed, not from a login.
  - New private features go under `src/app/(private)` only. Public pages must never import from private routes.
  - Anything that must be visible publicly goes in `/` or `/sources` and must come from `src/data/assumptions.ts` entries that are fine to publish (not `ownerOnly`).
  - Private-only data (investor notes, alternatives) stays out of public pages; keep `import "server-only"` on server data modules.
- Secrets only in `.env.local` (gitignored) and Vercel env vars; `.env.example` has empty values. Only env vars now: `NEXT_PUBLIC_CONTACT_EMAIL`, `NEXT_PUBLIC_SITE_URL`.

### OS content rules (every page, every session)
- **One question per page**, defined in `nav.ts`. The page opens with `PageHeader`: the question in small type, then the **answer as a headline insight** (one sentence, numbers computed from assumptions, never typed in) and the key number's status badge.
- **3–5 visuals max** per page. Prefer KPI tiles, charts, diagrams, timelines and gate bars. Tables, long lists, notes and fine print go in a collapsible **"Show details"** drawer (`Details`).

- Laptop-first (1280–1920 px), still usable on phones. New page = add the tab to `nav.ts`, use the page kit, put `os-detail` on anything that should disappear in presentation mode.

## 11. Simulation (`/sim`) — the showpiece
**Engine** (`/src/sim`, pure TS): discrete-time simulation, deterministic + seedable, independent of rendering, unit-tested.
Flow: collection points (Bangalore map, stylised) → inbound trucks → weighbridge → bale yard → sorting line → shredder → wash line (float-sink) → dryer → extruder → pelletizer → QC lab → packing → finished goods → outbound trucks to buyers.
State per machine: status (running/idle/down/maintenance), throughput, utilisation, energy.
KPIs: tonnes in/out, yield %, energy kWh/t, water use, uptime, inventory per stage, cost/kg, revenue, margin/kg, EPR credits generated, cash.
Controls: play/pause, speed 1x→1000x, day/night cycle, scenario sliders (feedstock price, pellet price, throughput, shifts, power tariff, contamination %), events (machine breakdown, monsoon supply dip, price shock).

**Visual layer** (react-three-fiber):
- Isometric orthographic camera, low-poly procedural models built in code (trucks, forklifts, bales, machines, conveyors, silos, buildings, trees). No copied or branded assets.
- Pastel/brand palette, soft shadows, ambient occlusion feel, smooth camera pan/zoom/rotate + reset.
- Moving trucks along paths, forklifts carrying bales, material visibly flowing on conveyors, machine status lights.
- Floating glass UI: top KPI cards, right detail panel on click (any truck/machine/zone), bottom "batch tracking" timeline (Received → Sorted → Washed → Pelletized → QC → Dispatched), bottom-right tabs (Docks / Machines / Trucks).
- Performance: instanced meshes, 60fps on a normal laptop, graceful fallback on mobile (2D schematic view).
- Build order: engine + 2D schematic first (numbers correct), then 3D.
